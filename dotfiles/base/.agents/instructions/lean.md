# Working Contract — lean

## Preferences and boundaries

- Keep scope fixed; no repo-wide sweeps unless asked. Surface changes to APIs, types, schemas, permissions, invariants, and transaction boundaries; update affected code, tests, and docs together. An agent-authored plan does not authorize execution.
- Prefer precise domain names/types and narrow interfaces. No speculative abstractions, backward-compatibility shims, silent defaults, or bookkeeping without a concrete consumer or failure to address. Delete dead code. Vet dependencies for maintenance, transitive weight, license, and performance cost; explain the choice and remove unused dependencies.
- Do not run formatters, change pinned Rust nightlies, or work on CI unless explicitly asked. "fix ci" authorizes reproducing locally (repo Dockerfiles on Linux), committing, pushing, retriggering with `gh`, and iterating until green.
- No code comments except external constraints, public API contracts, legal/lint/safety requirements, justified suppressions, or explanatory issue/PR links. State the constraint directly, never through roadmap/phase references; follow `comment-cleanup` for existing unresolved constraint warnings and remove other failing comments you touch. Explain unavoidable workarounds and their removal conditions in the reply.

## Execution

- Use task-specific skills when useful; do not load `do` solely because work is substantive. Honor requested workflows and their procedures. Explicit skills require the named workflow or outcome; reading a procedure grants no additional scope or authority.

## Environment and changes

- macOS/Linux: prefer native search, otherwise `rg`/`fd`, not `grep`/`find`. Use `jaq`, not `jq`/`yq` or parser scripts, for structured data. For non-JSON formats read `~/.agents/instructions/structured-data.md`. Use `fastermod`, not `sed`/`perl`, for renames across a tree: `fastermod --rename OLD NEW .` (binding-aware, fails closed), `--ident` (identifier tokens), `-S` (case-preserving text). Non-TTY runs preview without writing; `--apply` writes. For non-trivial renames read `~/.agents/instructions/fastermod.md`. Rust uses `kache`; Linux musl links with `mold`.
- Scratch and worktrees belong in repo `.work/tmp` and `.work/wt/<name>`, never system temp. Ignore `.work/` through `.git/info/exclude` before writing; set `TMPDIR` accordingly. `.work/` is strictly disposable: assume it can be deleted entirely. Never store durable plans, handoffs, resume state, or required results there. Commit project records under tracked paths such as `docs/` and deliver them in the primary checkout outside `.work/`; a scratch-worktree commit or final `.work/` link is insufficient. Durable records must contain the conclusions and reproduction instructions needed without scratch artifacts.
- Repositories live under `~/repos`, never `~/d`; `~/usr` stays where it is.
- Proactive `cleanup` sweeps require system disk <16 GiB available; hooks notify, never poll. Without a hook, run `agent-disk-pressure notify` after the first necessary shell command in the same tool call, preserving its exit status; do likewise after out-of-space failures. Recheck `agent-disk-pressure status` before each batch; stop at >=16 GiB or unknown. Retire your own completed lanes normally. Preserve live, leased, parked and unknown work; never recursively sweep `.work/`. Workers relay pressure to the parent.
- Commit and push completed, verified changes without waiting for another request; stage only your work. Use Conventional Commits: `type(scope): subject`, types `feat|fix|perf|refactor|docs|test|build|ci|chore|revert`, lowercase imperative subject at most 72 characters, no final period. The body explains why; contract changes use `!` or `BREAKING CHANGE:`.

## Replies

Be direct; disagree when warranted. Keep replies short: result, verification gaps, and decisions needed. After long-running or delegated work use Goal / Done / Next / Needs you, carrying forward unresolved user decisions and manual steps. Under run-until-done authority ("don't stop", "going to sleep", `/sleep`), settle choices inside it and act on your own recommendations without stopping to ask or report; Needs you lists only what a missing fact, credential, or ungranted effect blocks, with its unblock condition. Do not turn a one-session correction into a shared preference.
