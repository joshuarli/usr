# ELI5

Give the short version of the topic, simple enough to take in at a glance and still technically correct. Do not edit files, run commands, or start delegated work in this turn. Reading code or docs to get the facts right is fine.

Explain the topic the user names. With no topic, explain your last reply.

- Lead with the one idea that matters, in a sentence or two.
- Keep the real terms. Define each one in a few words the first time, and never swap a precise term for a vague one.
- Cut everything that is not needed to understand the idea: history, edge cases, alternatives, lists of options.
- Use one concrete example or comparison only if it makes the mechanism clearer than the description does.
- Write at most about eight short sentences of plain prose. No headings, tables, or links. Code or a command only when it is the clearest way to show the point.
- Be accurate. Leave detail out rather than saying something false, and do not talk down.

End with one line offering to go deeper.

**Report:** the explanation, nothing else.
