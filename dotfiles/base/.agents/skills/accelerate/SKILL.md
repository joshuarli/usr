# Accelerate

Change the operating method, not the owner's goal or acceptance floor. More agents are one possible remedy, not the definition of acceleration. Use [orchestrate](../orchestrate/SKILL.md) and its [parent steering checkpoint](../orchestrate/references/campaigns.md#parent-steering-checkpoint).

- **Find the limiting stage first.** Inspect recent substantive outcomes, ready work, rejected proposals, queue wait, and check durations. Separate implementation, verification, environment repair, and tooling. A busy fleet or many metadata commits may conceal little progress. Use existing evidence; do not start a new measurement platform.
- **Match the remedy to the cause.** When preparation is starved, launch disjoint ready work within measured headroom. When verification or review is saturated, cap provisional work and reduce writers; group compatible candidates or reuse qualified complete evidence. Run `perf-gate-ready -s` before adding width and respect shared databases, services, caches, and outputs, not just file ownership. Do not claim a speedup from a busy-host timing sample.
- **Deliver coherent slices.** Combine related slivers and prioritize shared repairs that unblock consumers. Do not pull in unrelated stretch work or narrow a truthful contract to satisfy an internal score. A wider ownership grant belongs in the parent's brief; it does not expand product or publication authority.
- **Make one bounded intervention.** Give a reproduced tool or prerequisite problem an owner, an exit test, and the next real item it must unblock. Classify false rejection, actual regression, newly exposed existing debt, and unavailable evidence separately. Test a policy correction against both useful improvements and real regressions; never blanket-suppress failures to improve throughput.
- **Preserve acceptance.** Follow the campaign reference's exact-tree validation and provisional/accepted distinction. Small commits can share a bounded global acceptance wave only when owner and repository requirements permit it. Focused checks and qualified reuse do not waive required final scope. A failed or stale measurement remains invalid.
- **Reassess instead of repeating.** Apply the ruling, update current instructions, and notify affected lanes. Retry parked work only when its named condition changes. After the next validation wave, compare substantive progress and the limiting stage again. Continue a healthy method; do not keep optimizing the coordinator instead of delivering.

**The test:** the next useful delivery has a shorter or better-supported path through the limiting stage without lost coverage, false contracts, or new authority. Keeping or reducing the lane count can be the correct result.

**Report:** the bottleneck, evidence, intervention, next substantive milestone, checks preserved, and provisional work remaining. Distinguish observed gains from unmeasured expectations; report lane changes only when relevant.
