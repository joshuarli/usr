# Accelerate

The owner judges the current pace too cautious. Re-plan the running work now,
under the existing [orchestrate](../orchestrate/SKILL.md) and campaign rules;
this skill changes the settings, not the contract.

- **More lanes.** Count running lanes against ready work with no owner and
  launch the difference this turn. Re-read the machine's measured load, memory,
  and swap, then raise the width to the new margin instead of the old one.
- **Wider lanes.** Merge slivers that share files into one slice per lane, and
  hand each lane its whole workstream remainder, not the next item. Brief a
  resumed lane with everything now ready for its files.
- **More ambition.** Pull in the stretch items: the cross-cutting refactor, the
  deleted legacy path, the design task parked as "later". Give the hard
  remainder a stronger tier rather than shrinking it. Start the item's
  independent part now and leave a named seam for the rest.
- **Bolder staggering.** Start dependents on the unmerged base when their files
  are disjoint. Integrate in small groups while the next tranche runs. Split
  serialized verification into parallel groups on disjoint inputs, and give
  loop speed an owner if it is the critical path.
- **Blockers.** For each parked or reported blocker, decide this turn: resolve
  it (cross-boundary change, widened contract, fixed rule or checker, stronger
  lane with the extra files), or defer it into its own item and route the lanes
  around it. Re-read any list of owner decisions and settle every entry the
  evidence allows. Ask the owner only about product behavior, public contracts,
  or authorization.
- **Keep the floor.** Acceleration does not waive acceptance. Lane contracts,
  worktree ownership, no-overlap writes, merge-then-verify, and the closing
  checks stay as written. Back off width when the machine shows swap, OOM, or
  load that would invalidate a perf gate, and say so.

**The test:** after this turn there are more lanes running, each owning a larger
slice, no lane is parked on a technical blocker, and every deferred blocker is a
named item.

**Reply:** lanes before and after, what was widened or pulled in, blockers
resolved or deferred, the load the new width runs at, and any decision that
truly needs the owner. Keep it short.
