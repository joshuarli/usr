# Agent setup

Use [`sbx`](sbx-spec.md) when running coding agents in a native macOS Seatbelt process sandbox; Linux sandboxing is out of scope. It exposes the current directory read/write and makes the tracked global skills/instructions available read-only without importing host agent authentication state. This is weaker than a VM; review the security specification and run its platform integration checks before using it for sensitive projects.

## Advisory decision routing

`orchestrate` consults the local `decide route` CLI by default when a nontrivial delegated task has evidence suitable for safe external inference. **Reuse your existing `cf auth login` session:** create a structured, validated JSON `TaskBrief` using `decide route --guide`, then pipe it into `decide route --baseline worker`. With no explicit REST credentials, it runs `cf ai run @cf/cloudflare/clef-flash --body @/dev/stdin`. cf resolves the OAuth profile and account, and refreshes tokens without exposing them to `decide`. Check sign-in with `cf auth whoami`. `decide doctor` checks local config and CLI presence, not live OAuth validity.

Explicit `CLOUDFLARE_API_TOKEN` and `CLOUDFLARE_ACCOUNT_ID` still take priority for the direct REST client. This does not create credentials or change Cloudflare settings. Use a recent cf CLI with the `ai run` command. Live `decide eval --live` still uses direct REST credentials.

Do not send repository source, credentials, full transcripts, sensitive internal logs, or customer data. The route command accepts only a bounded, evidence-bearing JSON brief on stdin; plain-text task titles are rejected, and missing evidence causes a local abstention. It never prints the brief. Missing cf/login credentials, quota, provider errors, or an explicit `DECIDE_ROUTING=off` cause the existing deterministic router to remain in control; they do not block coding work. The CLI's tier advice never grants extra tools or model/provider changes. See [decide CLI](../tools/decide/README.md) and [orchestrate](../dotfiles/base/.agents/skills/orchestrate/SKILL.md) for limitations, confidence heuristics, and evaluation.

## Instructions and skills

[`dotfiles/base/.codex/AGENTS.md`](../dotfiles/base/.codex/AGENTS.md) remains the normal shared contract. Other harness adapters still point to it. Claude's `CLAUDE.md` and Codex's higher-precedence `AGENTS.override.md` instead load a small bootstrap; startup hooks select the normal contract or the lean contract for Opus 5.5 in Claude and Sol 6.1 in Codex. The contracts are alternatives, not layers. See [instruction profiles](model-profiles.md) for activation, fallback, and fresh-session boundaries.

| Harness | Global instructions | Shared skills |
| --- | --- | --- |
| Codex | `~/.codex/AGENTS.override.md` (profile bootstrap) | `~/.agents/skills/` |
| Claude Code | `~/.claude/CLAUDE.md` | `~/.claude/skills/` |

**Routing coverage:** both instruction profiles and all nine harnesses share the `orchestrate` delegation policy. All standard coding subagents, including those launched outside `orchestrate`, use the `pi-subagent-bridge` MCP server or CLI — except OpenCode, which never uses the bridge and delegates only through OpenCode native subagents pinned to `opencode/inkling-2-small-free` (scout `low`, mechanic `medium`, worker `high`, expert `max`); when the top-level model is free, every tier must use free models, and there is no `god` tier anywhere. New `expert` tasks use Antigravity CLI `gemini-4-hydrogen-xhigh` exclusively; native Claude/Codex `god` is retired and Gemini 4 Carbon is not accessible on this account. This is a shared instruction policy, not an interception mechanism; no hook gates native subagents. When the bridge exhausts capacity, only scout/mechanic/worker can use tier-matched native subagents, as `orchestrate` describes; expert fails closed rather than choosing another provider. `decide` is optional advisory routing only. After updating `usr`, run `sh sync plan`, `sh sync`, and `sh sync doctor`.

Install Node.js 26.13.1 and its distribution-bundled npm (without an npm registry query) with `sh sync tools nodejs` on macOS arm64 or Linux x86_64 and arm64. No-argument `sync tools` also installs Node.js on those platforms, preferring the sync-managed runtime over any `node` earlier on `PATH` when it exists. Command Code requires Node.js 26.12.0+ and is installed by default with `sh sync` (or individually with `sh sync tools cmd`), into `~/.local/share/command-code` (or `$XDG_DATA_HOME/command-code`). Sync the tracked configuration with `sh sync`, then run `cmd login` yourself. The installer never touches Command's `~/.commandcode` credentials or sessions.

Command shares the canonical global instructions and discovers `~/.agents/skills/` without duplication. Its settings start in unrestricted `yolo` mode and omit the default commit co-author trailer. Taste learning is off per host via `cmd config set taste-learning false --scope user`, persisted in the untracked `~/.commandcode/config.json`; `/taste` re-enables it, and a project can override with `taste-learning-project`. This keeps it from creating `.commandcode/taste/` in every repository. Use `/skill:<name>` if a built-in command shadows a skill. Command sessions run the pinned `deepseek/deepseek-v4.1-flash` model at `max` effort, but delegated work uses the shared Pi SDK bridge instead of `Explore`/`General`.

fx is opt-in via `sh sync tools fx` (pinned, checksum-verified native Vercel Labs release for macOS or Linux on arm64/x86_64). The tracked `~/.fx/AGENTS.md` links to the canonical instructions and `~/.fx/settings.json` selects Vercel AI Gateway's `meta/muse-spark-1.3-contributor` for main sessions; delegated work uses the shared bridge. No secrets, sessions, or auth tokens are checked into Git. Authenticate interactively with `fx login vercel` or `fx setup`; then use `fx`, `fx ask --json "task"`, `/skills`, and `$orchestrate`. Meta's Contributor tier permits training on prompts and outputs: do not use it for code or data that cannot be shared under those terms.

fx uses `auto` permissions with Contributor for permission reviews (instead of its more expensive default reviewer); it disables generated titles and binary auto-upgrades. This is not a sandbox: verify fx's state/auth access before placing it in `sbx`. `~/.fx/sessions/` and credentials remain local. `/resume-session fx <ID>` does an exact, read-only file handoff where possible, while `fx resume <ID>` resumes the original conversation. Use `fx status --json`, `fx doctor`, and `fx usage` for diagnosis and bills.

The [Pi SDK + pi-subagents bridge](../tools/pi-subagent-bridge/README.md) is the shared executor for every harness except OpenCode. It pins expert to Hydrogen XHigh on Antigravity CLI without fallback, and retains the Codex → Command Code → Pi routes for lower tiers, nesting limits, and known admission/fallback defects. Parents retain worktree scope, independent proof, diff review, and integration. Command Code stays leaf-only; native Pi children can delegate one additional generation within typed tier ceilings. Muse workers use Contributor mode, which permits Meta to use prompts, code, and outputs for training. See [Pi setup](pi.md) for the current archive-based installation, authentication, intercom boundary, and proposed move to `pi-build`.

For cross-harness continuation, `/resume-session <agent> <session-id>` recovers a named local transcript and continues work in the **current** agent; it does not reopen the old agent's native process. It reads each harness's local transcripts directly; DeepSeek TUI and fx use their local files when readable. In Pi, invoke it as `/skill:resume-session <agent> <session-id>`; in Codex, use `$resume-session <agent> <session-id>`.

The tracked skills live in `dotfiles/base/.agents/skills/`. Directory links and allowlists keep harness state outside the repository. No native `god` profile remains in `dotfiles/base/.claude/agents/`, and the bridge has no `god` tier. For a custom `DSH_HOME`, install the DeepSeek adapter at `${DSH_HOME}/AGENTS.md`; `DSH_AGENTS_HOME` controls shared skill discovery.

[`SKILLS.md`](../SKILLS.md) explains skill selection and the `/do` and `/yea` workflows. To invoke `/do` directly, use `$do <task>` in Codex or fx, `/do <task>` in Claude Code, Muse Code, or OpenCode. Codex also provides `/skills`. Antigravity uses `/<skill-name>`. DeepSeek Harness loads matching skills through its skill tool. In interactive Muse Code, invoke an explicit skill with a leading `/<skill-name>` (for example `/refactor-python`, not `/skill <name>`); `/skills` lists skills and `/skills reload` refreshes after changes. A mid-sentence mention does not inject the body. Muse Code API, `muse serve` raw text, and headless (`muse exec`) sessions have no slash injection: when the user explicitly names an explicit-only skill and the skill tool rejects it as disabled, read the skill body directly (`~/.agents/skills/<name>/SKILL.md`, project skills under `.agents/skills/`) and work under it within existing scope and authority.

Codex native memories are enabled for advisory cross-session hints. Native extraction uses Luna, consolidation uses Terra, and background work waits at least 12 hours after activity with at least 50% rate-limit headroom.

Antigravity CLI reads skill descriptions and may activate eligible skills automatically, and its skill frontmatter allows only `name` and `description`. Keep explicit-only workflows out of its automatic selection; the user requests one in plain language or with `/<skill-name>`.

Harnesses use native skill metadata and discovery paths. The checker at [`skills-check.sh`](../dotfiles/skills-check.sh) validates tracked skill metadata. See [the skills guide](../SKILLS.md) for invocation rules.

## Harness configuration

Codex defaults to `gpt-6.1-terra` at `medium` effort. All child tiers, including expert, must use `pi-subagent-bridge`. The root expert lane pins Antigravity `gemini-4-hydrogen-xhigh` at `xhigh` with no fallback; no native Codex god is permitted, and there is no `god` tier. These models select multi-agent V2, whose eight resident-thread slots include the parent. The V1 `agents.max_depth` setting does not restrict V2 nesting; the orchestration skill instructs V2 children not to spawn other children.

The tracked configs are under [`dotfiles/base`](../dotfiles/base/). Review changes after a harness writes its own config. Claude may rewrite `settings.json`, Codex may append trusted projects to `config.toml`. Antigravity CLI owns `~/.gemini/antigravity-cli/settings.json` outright, rewriting model selection and `trustedWorkspaces` on launch, so that file is untracked and left in place. Never set or fall back to Gemini 4 Argon, and never route to Gemini 4 Carbon, which this account cannot access. Antigravity direct sessions replacing Gemini 3.8 Flash should explicitly select an available Gemini 4 Hydrogen slug (e.g. `gemini-4-hydrogen-high`); expert dispatches pin `gemini-4-hydrogen-xhigh` through the shared bridge and require `agy models` to list it. Check `agy models` rather than assuming a model is available. OpenCode restores its `cli.json` when missing, so install its tracked symlink while the client is stopped.

The configured harnesses allow unrestricted actions. Claude disables sandboxing and uses `bypassPermissions`; Codex sets `approval_policy = "never"` and `sandbox_mode = "danger-full-access"`; Muse uses `:unrestricted`; OpenCode has an allow-all permissions rule; Command Code defaults to `yolo`. fx uses `auto` permissions with the Contributor reviewer instead of the default higher-priced reviewer. See the tracked configs for hook and notification details.

`reset-agents` clears Claude, Codex, Muse, and OpenCode state under `$HOME`; pass one harness name to reset only that harness. It keeps dotfiles-managed files and `.credentials.json`, `auth.json`, and `mcp_credentials.json`. It rejects paths outside the resolved home and paths with symlinked components. Run it only when you intend to reset state. See its [implementation](../dotfiles/base/.local/bin/reset-agents) for supported paths.
