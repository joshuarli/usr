# Home-directory sync

`dotfiles/base` applies on every OS. `dotfiles/darwin` and `dotfiles/linux` add the matching OS layer. `make` selects layers from `uname` and applies them to `$HOME` with `dotfiles/sym`.

Each relative path can belong to one layer. The `layers` target rejects duplicate claims before sync. `sym` creates relative symlinks for files. A directory with a `.sym-dir` marker is linked as one unit. Git ignore rules determine which files `sym` sees.

Run `make plan` to preview the links. It does not run `dl`. A `CONFLICT` means the target contains a path that `sym` cannot safely replace. Resolve it before syncing. `make` runs `dl` and then applies each layer. If a download fails, sync still runs and `make` returns a failure. The `TARGET` variable changes the symlink destination; `dl` still installs into `$HOME/.local/bin`.

`dl` installs supported tools into `$HOME/.local/bin`, except package roots that need to keep their own dependencies together. For release-backed downloads, it records each asset's ETag under `${XDG_STATE_HOME:-$HOME/.local/state}/dl` and downloads again when the ETag changes. If a release cannot be checked, `dl` keeps an installed tool and warns. Grok, Muse, Codex, Claude, and OpenCode 2 come from direct platform downloads. OpenCode 2 is installed as `opencode2` so it can coexist with OpenCode 1. `dl` installs `grok`, `muse`, `codex`, and `opencode2` only when their executable is missing. It installs `@deepseek-ai/dsh` from npm's `next` tag and `@deepseek-harness-tui/dsh-tui` under `${XDG_DATA_HOME:-$HOME/.local/share}/dsh` when their recorded npm versions change. DSH's `next` release includes the DeepSeek Search and Fetch API providers selected by the tracked TUI patch. The tracked launcher supplies `DEEPSEEK_API_KEY` from `vault`; on hosts without `vault`, it uses an exported `DEEPSEEK_API_KEY` and fails with an error if neither source is available. Search and Fetch are billed per successful request ([DeepSeek Search & Fetch docs](https://api-docs.deepseek.com/guides/search/)). The TUI package currently carries a disabled `tool-ralph` row that DSH no longer ships; `dl` removes that exact row and fails if its shape changes. Node.js `^22.19` or `>=24`, npm, Python 3, and pnpm 10 or newer must already be available. The tracked `dsh` launcher starts the `dsh-tui` command and its `dsh-tui` profile; `dsh web` and other explicit profile invocations use the core CLI. The Antigravity CLI is installed as `agy` by Google's installer with `$HOME/.local/bin` passed as its destination; `dl` installs it only when missing. Claude Code stores its versioned binary under `${XDG_DATA_HOME:-$HOME/.local/share}/claude/versions` and links `$HOME/.local/bin/claude` to it. On macOS and Linux, `dl` migrates an old direct Claude install when a saved ETag is present and `file` identifies the launcher as a Mach-O or ELF binary. It leaves script launchers alone. If `file` is unavailable, `dl` warns and keeps the launcher. Run `dl grok muse dsh codex claude opencode2 antigravity` to install only those tools. Muse, Codex, and Claude use `jaq` to read release metadata. `dl` installs `jaq` when Muse, Codex, or Claude needs release metadata. Codex's bundle lives under `${XDG_DATA_HOME:-$HOME/.local/share}/codex`.

`dl` also installs the `mactop` app and LaunchAgent. On Linux, `fd` and `rg` use static musl archives, and `mold` is installed only on x86_64. Muse, Codex, and Claude downloads are checked against vendor SHA-256 values. Grok, OpenCode 2, and the other downloads rely on TLS.

The repository's `bin` symlink points to `~/.local/bin`, where tracked scripts and downloaded tools live together. Only the scripts under `dotfiles/*/.local/bin` are tracked.

Deleting a source file leaves its home-directory symlink dangling. Remove that link too, or run `sh dotfiles/sym -d` on the layer before deleting the source. To experiment with `sym`, pass a scratch target with `-t`; without it, `sym` targets `$HOME`.

The `macos/` directory is not part of the layer sync. Run its setup scripts by hand. `macos/setup-macos` provisions Homebrew, packages, Touch ID for `sudo`, and local DNS. `macos/macos-lean.py` disables selected services and is never part of the default setup.
