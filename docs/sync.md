# Home-directory sync

`sh sync` selects `dotfiles/base` and the matching OS layer, then applies them to `$HOME` with `dotfiles/sym`. Each relative path belongs to one layer. `sh sync layers` rejects duplicate claims. See [`sym`](../dotfiles/sym) for link rules.

Run `sh sync plan` to preview links. Resolve each `CONFLICT` before syncing. `sh sync links` applies only the layer links, without `dl` or host setup, and `sh sync tools ish` runs `dl` for the named tools only. `sh sync` applies links before running `dl`; a failed download leaves the links in place and returns failure. `TARGET` changes the symlink destination, but tools still install under `$HOME/.local/bin`.

`sh sync doctor` inspects the installed environment without changing managed files or host settings. It reuses `sync plan` to report missing, conflicting, or obsolete layer links, checks ownership records and default `dl` launchers (`sh dl --list`), verifies shared agent entry points, and checks Homebrew bundle state on macOS or the installed Unbound configuration on Alpine. It may create temporary scratch files, which it removes. It performs no installation, package upgrade, sudo operation, or intentional network request; a nonzero exit means at least one problem was detected. Use `sh sync plan` to see exact link repairs before applying anything.

`sh sync uninstall` removes recorded layer links and installed tool paths. It leaves unrecorded pre-existing links and native launchers in place. Ownership records live under `${XDG_STATE_HOME:-$HOME/.local/state}/sync`. See [`dl`](../dl) for tool installation and update behavior.

`cf` is installed by default from a pinned npm package under the managed Node.js runtime. `agent-browser` is installed the same way into `${XDG_DATA_HOME:-$HOME/.local/share}/agent-browser`; change `AGENT_BROWSER_VERSION` in `dl` to upgrade. It drives the system Chrome/Chromium, so no browser download is needed; run `agent-browser install` only if you want a managed Chrome for Testing instead. `stuff` is installed by default from its latest GitHub pre-release; `sh dl stuff` updates or reinstalls it.

The base layer also links a `yt-dlp` shim. It downloads the upstream nightly on first use and checks for a newer nightly at most once a day; `vdl`, `mdl`, and `mpdl` run through it. Remove `${XDG_DATA_HOME:-$HOME/.local/share}/yt-dlp` and `${XDG_STATE_HOME:-$HOME/.local/state}/yt-dlp` to reclaim the download and its state.

`sh sync` also runs host setup: macOS installs Homebrew packages, while Alpine Linux installs the sync prerequisites and configures Unbound and DNS. These steps can use `sudo`. Other Linux distributions skip Unbound setup. Touch ID, macOS DNS, and Tailscale SSH setup are manual; the packages step installs Homebrew's `tailscale`, the only macOS variant that serves Tailscale SSH. See [`setup-macos`](../host/macos/setup-macos) and [macOS preferences](macos-preferences.md).

On macOS, `sh dl ghostty` or `sh dl ghostty-custom` installs the latest `release-*` prerelease from `joshuarli/ghostty`. It verifies `SHA256SUMS`, installs `Ghostty Custom.app` with a `~/.local/bin/ghostty-custom` symlink, and records the release asset identity. Set `GHOSTTY_APPLICATIONS_DIR="$HOME/Applications"` if `/Applications` is not writable. It will not overwrite an existing unmanaged app or launcher; `sh sync uninstall` removes a dl-managed installation.

**Ghostty shader reload:** After `git pull`, run `sh sync links` to link any new shader file. Ghostty only rebuilds a shader on config reload when the configured shader path changes; editing GLSL at the same path alone may leave an existing terminal using cached code. Open a new Ghostty window or fully quit and relaunch for source-only changes. Run `python3 -I dotfiles/ghostty-shader-test.py --demo` in Ghostty to verify the animation.

`sh dl fx` is an optional pinned native install; no-argument `dl` does not install fx. The `~/.fx/AGENTS.md` and `~/.fx/settings.json` files are dotfiles-managed links; fx credentials, sessions, and all other mutable state stay local. fx auto-updates are disabled in the tracked profile. Change `FX_VERSION` and its checksums in `dl` to upgrade.

The `host/macos/` directory is not part of the layer sync. `agent-learn` and its Codex hook come from the base layer; its LaunchAgent template is installed only when you pass `--schedule` to `agent-learn enable` on macOS. The commands run the agent-memory package installed in `$AGENT_MEMORY_VENV` (default `~/d/agent-memory/.venv`); see `~/d/agent-memory/docs/install.md`.

`sh dl player` installs the latest tagged Player release from `joshuarli/play`. It verifies the release `SHA256SUMS`, installs `~/Applications/Player.app` and a `~/.local/bin/player` link on macOS (set `PLAYER_APPLICATIONS_DIR` to change the app location), and installs `~/.local/bin/player` on x86-64 Linux. It refuses an unmanaged existing app or launcher; remove a manually installed copy first. The macOS app is ad-hoc signed and not notarized, so `dl` clears the quarantine attribute. `player` is in the default target set on x86-64 Linux and optional on macOS.

`sh dl ffmpeg` installs the `ffmpeg` and `ffprobe` pair from the newest `YYYYMMDD` or `YYYYMMDD-rN` release of `laputa-systems/ffmpeg-build` (discovered through `releases.atom`) for `aarch64-apple-darwin`, `x86_64-unknown-linux-musl`, or `aarch64-unknown-linux-musl`. It verifies `SHA256SUMS`, stages the `tools` archive under `~/.local/share/ffmpeg/releases/<tag>-<triple>/`, smoke-tests both commands, then points `~/.local/share/ffmpeg/current` at it and links `~/.local/bin/ffmpeg` and `~/.local/bin/ffprobe` through `current`. A failed download, checksum, extraction, or smoke test keeps the previous pair; an unmanaged launcher is refused. `ffmpeg` is in the default target set on those three platforms, and `doctor` and the Alpine verifier check both launchers.

`sh dl zzz` installs the `zzz` CLI from the newest `release-*` release of `laputa-systems/zzz` (discovered through `releases.atom`) as a raw static binary for Linux `x86_64` and `aarch64` musl static; the release publishes no `SHA256SUMS`. `zzz` is in the default target set on Linux and skipped on other platforms. `encode` needs macOS and exits early elsewhere.

Sync prunes a recorded link that points into a layer whose source is gone; `sh sync plan` lists these as `PRUNE`. A link copied from a layer symlink points elsewhere, so it stays, as do links `sh sync` did not create. Remove those yourself, or run `sh dotfiles/sym -d` on the layer before deleting the source. Test `sym` only with `-t <tmpdir>`; without it, `sym` targets `$HOME`.
