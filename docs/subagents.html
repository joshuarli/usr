Hard rules

  1. The bridge admits scout, mechanic, worker and expert. There is no god tier.
  2. Expert is the strongest lane: use it for exceptional architectural decisions and adversarial review, never as a size-based upgrade.
  3. Top-level OpenCode, Devin and Command Code sessions never use the bridge, at any tier or as a fallback. Command Code uses native usr-* agents; HY4-medium worker is an explicit pilot, not a default. When the OpenCode top-level model is free, every tier runs a free model (its configured tier agents use opencode/hy4-flash-free).
  4. Top-level Antigravity CLI sessions use native usr-* subagents only. Its flash/pro model selectors do not enforce exact model IDs or efforts: verify or block the lane. God is a direct main-session mode.
  5. Copilot CLI is an unqualified native-only pilot. Its named usr-* lanes require observed model and effort attestation before dispatch. Block unavailable or unattested lanes; never use Auto, built-in agents or the bridge as a fallback. Children are leaves.
  6. Claude Code, Codex and Pi sessions use the bridge for every tier; the bridge owns provider fallback (Command Code → ordered Pi → Codex), only before edits, only along admitted routes.
  7. Command Code native children cannot spawn another subagent. Native frontmatter pins and parent scoping are instructions, not bridge-enforced admission; model overrides and unsupported effort can bypass intended settings.
  8. An admitted session keeps its recorded model and route. A task failure, rejected acceptance check or scope change is not a provider failure and never authorizes a replacement worker.
  9. Codex and Command Code workers are leaves. Pi workers may fan out one nested generation to equal-or-weaker approved tiers; the typed ceiling is enforced per child, depth is 2, and options: { agentScope: "user" } is required for nested calls.
  10. Ban on delegation of gemini-3.8 / gemini-4-argon / gemini-4-carbon / gpt-6-astra / gpt-6.1-astra / gpt-6.2-astra / claude-fable / fable families in every harness, including every effort variant.
  11. The parent owns scope, worktrees, verification and integration in every harness. Agent output is a claim until the parent checks the diff and the acceptance proof.
See orchestrate for the routing contract and the bridge reference for admission, fallback and state semantics.
