# Handoff: align the agent-memory Worker build with the tsrs/prebuilt pipeline

## Why

`tools/agent-memory/cloudflare` still builds with `cf build` → Wrangler → esbuild,
typechecks with `tsc`, and treats `wrangler.toml` as the source of truth. The
`stuff` and `stats` repos moved to `tsrs` + a self-written Cloudflare Build
Output Specification + `cf deploy --prebuilt`; this project should match.

Reference commits:

- `stuff` `811d627`: tsrs emit, prebuilt spec, Wrangler removed.
- `stuff` `8fb023b`: Vite dev server, search bundle off esbuild.
- `stats` `1ae6ce1`: `vite build` + prebuilt deploy, `tsrs` for typecheck.
- `stats` `NOTES.md`: why the Workers Vitest plugin still pulls esbuild (not
  applicable here—this project uses `node --test`).

## Current state

- npm 12.2.1, Node 26.12.1; `package-lock.json`, not pnpm.
- `cloudflare/package.json`: `check` runs `tsc --noEmit`; `test` runs
  `node --test test/*.test.mjs`; dev deps include `typescript@7.0.2`,
  `wrangler@4.156.0`, `cf`, `miniflare@4.20260730.0`, `oxlint`.
- `make worker-bundle` runs `cf build --mode production`, which delegates to
  Wrangler/esbuild and emits one `bundle/index.js`.
- `cloudflare.config.ts` is generated by `cf migrate` from `wrangler.toml`; it
  uses `entrypoint: "src/index.ts"` and `exports.default` with `cache.enabled: false`.
- `scripts/deploy-gate.sh`, `scripts/provision.sh`, and the shared
  `/Users/josh/usr/Makefile` all read the D1 id from `wrangler.toml`.
- Tests import the built `bundle/index.js` directly:
  `test/harness.mjs` (`loadWorker`), `test/serve.mjs`, and
  `test/runtime.test.mjs` (Miniflare `scriptPath`). `test/status.test.mjs`
  reads the bundle as text to assert no test hooks.
- `src/` has 33 extensionless relative imports (`from "./db"`, `from "../auth"`).
- No wasm, no frontend, no Durable Objects; exports are just the default
  handler.

## Target

- `tsrs` typechecks and emits; `typescript` and `wrangler` leave devDeps.
- Build the Build Output Specification ourselves under
  `.cloudflare/output/v0/`; deploy with `cf deploy --prebuilt`.
- Ship the entry plus its local modules as separate ESM modules; no bundler.
- Keep npm. No Vite unless the owner wants `cf dev` (see below).
- `npm ls esbuild wrangler typescript` should be empty afterwards.

## Steps

### 1. Make relative imports explicit ESM

Workerd and Node ESM cannot resolve extensionless specifiers. Change all 33
relative imports from `"./db"` to `"./db.js"`, `"../auth"` to `"../auth.js"`,
etc. Type-only imports included. `moduleResolution: "Bundler"` still resolves
`./db.js` to `db.ts`, so no other change is needed. This is the main mechanical
edit and the thing most likely to be missed; the runtime tests catch it.

### 2. tsconfig

- Remove `"noEmit": true`; `npm run check` passes `--noEmit` instead.
- Add `"rootDir": "src"`, `"outDir": ".cloudflare/output/v0/workers/default/bundle"`,
  `"sourceMap": true`, `"noEmitOnError": true`, `"skipLibCheck": true`
  (required for tsrs `--fast`'s lazy declaration parsing).
- Keep `target`, `lib`, `module`, `moduleResolution`, strict flags,
  `verbatimModuleSyntax`, and `"types": ["@cloudflare/workers-types"]`.
  `cf workers types` is not needed because the project uses the workers-types
  package directly.

### 3. Dev dependencies and scripts

- Add `tsrs@0.20.1-ts7.1.0-beta` and `@cloudflare/config@0.29.0` (pin matches
  `cf@1.0.0-beta.26`).
- Remove `typescript`.
- Remove `wrangler` only after step 5 (scripts still parse `wrangler.toml`).
- Scripts: `"check": "tsrs -p tsconfig.json --noEmit --fast"`,
  `"build": "node scripts/build.mjs"`. Keep `test` as `node --test`.

### 4. Build script

Add `cloudflare/scripts/build.mjs`, modelled on
`stuff/crates/stuff-worker/scripts/build.mjs` minus wasm:

```js
import { execFileSync } from "node:child_process";
import { readdirSync, rmSync, writeFileSync } from "node:fs";
import { dirname, join, relative } from "node:path";
import { fileURLToPath } from "node:url";
import { loadAndParseConfig } from "@cloudflare/config";

const root = dirname(dirname(fileURLToPath(import.meta.url)));
const output = join(root, ".cloudflare/output/v0");
const worker = join(output, "workers/default");
const bundle = join(worker, "bundle");
const buildContext = { isPreview: false, mode: "production" };

rmSync(worker, { recursive: true, force: true });
execFileSync(join(root, "node_modules/.bin/tsrs"), ["-p", "tsconfig.json", "--fast"], {
  cwd: root,
  stdio: "inherit",
});

const modules = {};
const walk = (dir) => {
  for (const entry of readdirSync(dir, { withFileTypes: true })) {
    const path = join(dir, entry.name);
    if (entry.isDirectory()) walk(path);
    else if (path.endsWith(".js")) modules[relative(bundle, path)] = { type: "esm" };
    else if (path.endsWith(".js.map")) modules[relative(bundle, path)] = { type: "sourcemap" };
  }
};
walk(bundle);

const { result } = await loadAndParseConfig(join(root, "cloudflare.config.ts"), buildContext);
if (!result.success) {
  for (const issue of result.error.issues) console.error(`${issue.path.join(".")}: ${issue.message}`);
  process.exit(1);
}
const { worker: parsed, accountId, complianceRegion } = result.data;
const { entrypoint: _entrypoint, ...config } = parsed;
writeFileSync(join(worker, "worker.config.json"), JSON.stringify({
  ...config,
  manifest: { type: "complete", mainModule: "index.js", modules },
}));
writeFileSync(join(output, "config.json"), JSON.stringify({
  ...(accountId === undefined ? {} : { accountId }),
  ...(complianceRegion === undefined ? {} : { complianceRegion }),
  buildContext,
}));
```

Build the module map by walking the output, not a fixed list, so new routes
(the in-flight `generations.ts`) are included automatically. Clean the worker
directory first so deleted modules do not linger.

### 5. Tests and harness

- `test/runtime.test.mjs`: keep `scriptPath` at
  `bundle/index.js`, but add
  `modulesRules: [{ type: "ESModule", include: ["**/*.js"] }]`. Miniflare
  classifies `.js` as CommonJS by default.
- `test/harness.mjs` and `test/serve.mjs` import `bundle/index.js` directly;
  they keep working once imports carry `.js` extensions and all emitted
  modules sit next to the entry.
- `test/status.test.mjs` scans only `BUNDLE_PATH` text for test hooks. With
  multiple modules, walk every `.js` file under the bundle directory instead.
- Update the two "missing worker bundle" messages from
  `cf build --mode production` to `npm run build`.

### 6. Build/deploy wiring

- Shared `/Users/josh/usr/Makefile`:
  - `worker-bundle`: `cd $(WORKER_DIR) && npm run build`
  - `worker-check`: `cd $(WORKER_DIR) && npm run build && $(CF) deploy --prebuilt --dry-run --mode production`
  - `worker-deploy` already uses `--prebuilt`; keep it.
- `package.json` `build` script is the single build entry point; do not call
  `cf build` anywhere.
- `cf deploy` without `--prebuilt` delegates to Wrangler; once Wrangler is
  removed it fails. Make `--prebuilt` the only documented path.

### 7. Decide the config source of truth

`wrangler.toml` and `cloudflare.config.ts` duplicate the D1 id, domain, vars,
and bindings. The deploy gate, provision script, and Makefile parse the toml;
`cf migrate` regenerates the config from it. Two options:

- **A (aligned):** make `cloudflare.config.ts` the source of truth. Stop
  running `cf migrate --force`; teach `provision.sh` to update the `id:` in the
  config, and teach `deploy-gate.sh` / `DATABASE_ID` to read the D1 id from the
  config (a tiny Node helper importing `@cloudflare/config` is safer than
  `rg`/`sed`). Then delete `wrangler.toml` and `wrangler`.
- **B (intermediate):** keep `wrangler.toml` only as provisioning input and
  remove it from the build path. Scripts keep working unchanged, but the
  duplication remains.

Campaign decision CF1 currently says "`wrangler.toml` is the source of truth
and `cf migrate` regenerates `cloudflare.config.ts` ... no bundler beyond what
`cf deploy` runs." Option A changes that contract; get owner sign-off and
update `docs/CAMPAIGN-AGENT-MEMORIES-CLOUDFLARE.md` and the README worker
section together.

**Recommendation: A, in the same pass as the build change.** Once the build
leaves Wrangler, the TOML's only remaining job is regenerating a config that is
already checked in and gated, so two files own the same bindings, domain, and
vars. Keep the D1 id inline in `cloudflare.config.ts` (the config already has
it): have `provision.sh` replace that one `id:` line and give `deploy-gate.sh`
and `DATABASE_ID` a small Node helper that loads the config with
`@cloudflare/config` and prints the parsed D1 binding. Option B is only a
merge-timing fallback; don't make it permanent.

### 8. Optional Vite dev server

Only if `cf dev` is wanted. Add `@cloudflare/vite-plugin@2.0.0-beta.v.8` and
`vite@8.3.5`, a `vite.config.ts` with `cloudflare()`, and a `dev` script.
Change the config entrypoint to the module form
(`import * as entrypoint from "./src/index.ts" with { type: "cf-worker" };`)
and add `allowImportingTsExtensions` + `rewriteRelativeImportExtensions` to
tsconfig so `tsrs` still emits.

Known plugin bug: an `exports.default` entrypoint is treated as a named export
and the plugin emits `export const default`, which crashes workerd. Omit
`exports.default` when `mode === "development"`; see
`stuff/crates/stuff-worker/cloudflare.config.ts` for the exact conditional.
Do not change the production config for this. When the config switches to the
`cf-worker` import form, `scripts/build.mjs` must call `registerConfigHooks()`
from `@cloudflare/config` before `loadAndParseConfig` (the stuff-worker script
does this).

## Pitfalls

- Workerd/Node ESM require explicit `.js` extensions; the 33 imports are the
  main source of breakage.
- Miniflare treats `.js` as CommonJS unless the ESModule rule is added.
- Without `noEmitOnError`, `tsc`-style tools emit despite type errors and can
  deploy a broken bundle.
- `tsrs --fast` needs `skipLibCheck` for lazy declaration parsing.
- Do not hand-prune platform binaries from lockfiles; both npm and pnpm keep
  foreign optional entries and only install the matching one.
- The Build Output Specification is `v0`; `cf deploy --prebuilt` is the reader,
  so validate with `--dry-run` after any manifest change.
- The other agent has uncommitted work in this tree (routes, migrations,
  protocol). Rebase onto it; do not revert or stage it.
